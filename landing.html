PIN-protected endpoints

Default PIN: 1234
MethodPathAuthDescription
POST /sign/raw PIN Sign base64-encoded data → returns base64 signature
POST /sign/xml PIN Create enveloped XML digital signature
POST /admin/generate-keypair PIN Generate new RSA 2048 key pair on the token
POST /admin/generate-cert PIN Create a new self-signed certificate
POST /admin/change-pin PIN Change the token PIN (body: old_pin + new_pin)
POST /sign/raw
// Request body { "data": "aGVsbG8gd29ybGQ=", // base64-encoded payload "pin": "1234" } // Response 200 { "signature": "KGr5zTz2...", // base64 RSA signature "mechanism": "SHA256_RSA_PKCS", "label": "default" }
POST /verify/raw
// Request body — no PIN needed { "data": "aGVsbG8gd29ybGQ=", "signature": "KGr5zTz2..." } // Response 200 { "valid": true }
POST /sign/xml
// Request body { "xml": "<Invoice><id>1</id><amount>120</amount></Invoice>", "pin": "1234" } // Response 200 { "signed_xml": "<?xml version='1.0'...<ds:Signature>...</ds:Signature></Invoice>" }
POST /verify/xml
// Request body — no PIN needed, accepts "xml" or "signed_xml" { "signed_xml": "<?xml version='1.0'...<ds:Signature>...</Invoice>" } // Response 200 { "valid": true }
Virtuoso Journey Patterns
B

Sign & Verify Raw

Sign a base64 payload then verify the signature.

  1. POST /sign/raw — capture signature
  2. POST /verify/raw — assert valid: true
C

XML Sign & Verify

Sign an XML document then verify the enveloped signature.

  1. POST /sign/xml — capture signed_xml
  2. POST /verify/xml — pass response directly (accepts "signed_xml" or "xml") — assert valid: true
D

Health & Cert Checks

Assert service is up and certificate is valid — no PIN needed.

  1. GET /health — assert status: ok
  2. GET /certificate/info — assert key size = 2048
E

Wrong PIN / Lockout

Negative test: verify PIN lockout behaviour after 3 failures.

  1. POST /sign/raw with bad PIN × 3
  2. GET /health — assert is_locked: true
